# tetris — 워크스페이스 지시문

## 산출물 형태
- 게임 본체는 `tetris.html` 단일 파일. 외부 라이브러리, CDN, 이미지 파일 금지.
- HTML + CSS + Vanilla JS만 사용. 브라우저에서 파일을 직접 열면 동작해야 한다.
- 파일 하나로 유지하되 내부는 섹션 주석으로 구분한다: CONFIG / STATE / LOGIC / RENDER / INPUT / LOOP.

## 코드 규약
- 매직 넘버 금지. 모든 상수는 파일 상단 `CONFIG` 객체에 모은다.
- 보드와 조각 상태는 순수 함수로 갱신한다. 원본 배열을 직접 변형하지 않는다.
- 게임 로직(충돌, 회전, 점수)과 렌더링을 분리한다. 로직 함수는 canvas를 모른다.
- 게임 루프는 requestAnimationFrame + 델타 타임 기반. 프레임레이트가 달라도
  낙하 속도가 동일해야 한다.
- 함수는 50줄 미만. CSS 값은 `:root` 커스텀 프로퍼티로 정의한다.

## 테스트 (모든 태스크에 적용)

- 테스트는 `test/` 아래에 둔다. Node 내장 러너만 쓴다: `node --test test/`.
  외부 의존성·package.json·빌드 단계 금지. 게임 본체와 같은 원칙이다.
- `test/harness.js` 가 `tetris.html` 의 `<script>` 를 추출해 최소 DOM 스텁
  위에서 실행하고 내부 심볼을 돌려준다. **게임 코드를 테스트용으로 수정하지
  않는다.** 테스트가 프로덕션 코드에 맞춘다.
- 새 순수 함수를 만들면 그 함수의 테스트를 같은 태스크에서 추가한다.
- 수용 기준 중 **결정적으로 재현 가능한 것**(순수 함수, 점수 계산, 상태
  전이)은 테스트로 남긴다. 브라우저 렌더링·레이아웃·시각 상태는 예외다.
- 앞 태스크의 회귀 항목은 수동 재확인 대신 기존 테스트가 통과하는 것으로
  갈음한다.
- **`node --test test/` 가 통과하지 않으면 커밋하지 않는다.**

## 작업 절차
- 태스크는 `docs/tasks/T-*.md` 에 정의되어 있다. 배정된 태스크의 수용 기준을
  모두 만족시키고, 만족시켰다는 근거를 최종 출력에 적는다.
- 계획 문서 `docs/tetris-plan.md` 의 Phase 순서를 벗어나지 않는다.
- 계획에서 벗어나야 한다면 벗어나기 전에 부모 스레드에 알린다.
