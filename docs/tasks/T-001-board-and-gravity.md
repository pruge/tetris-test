# T-001 — 보드, 렌더, 중력 낙하

Phase: 0 · Status: Ready · Depends on: (없음)

## Summary

빈 저장소에 `tetris.html` 을 새로 만들고, 10x22 보드를 canvas에 그린 뒤
테트로미노 하나가 일정 속도로 내려와 바닥이나 기존 블록 위에 고정되고
다음 조각이 스폰되는 데까지 구현한다. 이 태스크에서는 사용자 입력을 받지
않는다. 화면을 열어두면 조각이 저절로 쌓여 올라가는 상태가 목표다.

## Scope

포함:
- `CONFIG` 상수 객체 (보드 크기, 셀 픽셀, 낙하 간격, 조각 모양/색 테이블)
- 7종 테트로미노 모양 테이블 (회전 4상태 전부 데이터로)
- `Uint8Array(220)` 보드와 순수 함수 `lockPiece`, `collides`
- canvas 렌더: 보드 격자 + 고정된 블록 + 현재 조각
- 델타 타임 기반 rAF 루프, 고정 낙하 간격 1000ms
- 스폰 위치가 막히면 게임 오버 (콘솔 로그 + 루프 정지로 충분)

제외 (다른 태스크):
- 키보드/터치 입력, 회전, 하드드롭 → T-002
- 7-bag, 홀드, 고스트, 락 딜레이, 점수, 레벨 → T-003
- 사이드 패널 UI, 디자인 → T-004

## Acceptance criteria

1. `tetris.html` 을 브라우저에서 직접 열면 (서버 없이) 즉시 동작한다.
2. 보드는 10열, 표시 20행이며 상단 2행 버퍼는 화면에 보이지 않는다.
3. 조각이 정확히 1초에 한 칸 내려간다. 개발자도구에서 rAF를 60→30fps로
   떨어뜨려도 낙하 속도가 변하지 않는다.
4. 조각이 바닥 또는 기존 블록에 닿으면 그 자리에 고정되고 새 조각이 스폰된다.
5. `collides()` 와 `lockPiece()` 는 인자로 받은 board를 변형하지 않는다.
   `lockPiece` 는 새 `Uint8Array` 를 반환한다.
6. 파일에 매직 넘버가 없다. 10, 22, 1000 등은 모두 `CONFIG` 에서 온다.
7. 보드가 천장까지 차면 루프가 멈추고 콘솔에 `game over` 가 찍힌다.

## Out of scope / 하지 말 것

- 라인이 꽉 차도 이 태스크에서는 지우지 않는다 (T-003).
- 회전 코드를 미리 넣지 않는다. 모양 테이블만 준비한다.
- CSS 디자인에 시간을 쓰지 않는다. 무채색 + 조각 색상만.

## Verification

브라우저에서 파일을 열고 30초간 방치했을 때 조각이 쌓여 게임 오버에
도달하는지 확인한다. 확인 결과를 최종 출력에 적는다.
