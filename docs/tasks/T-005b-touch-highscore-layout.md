# T-005b — 모바일 터치, 최고 점수, 레이아웃 정리

Phase: 3 · Status: Ready · Depends on: T-004 (`742542a`)
흡수: T-007 (레이아웃 후속 항목)

## Summary

세 가지를 한다. 터치 조작 추가, 최고 점수 localStorage 저장, 그리고 T-004
리뷰에서 나온 레이아웃 문제 정리. 셋 다 UI/입력 계층이라 한 태스크로 묶었다.

## 병렬 작업 주의

**T-005a 가 같은 파일을 동시에 수정 중이다.**

- 너는 INPUT 섹션, RENDER 섹션, `ui` 객체, `resetGame()`, CSS 를 소유한다.
- **LOGIC 섹션, `applyLineClears`, `lockAndSpawn`, `tryRotate`, 점수 계산
  함수를 건드리지 마라.** T-005a 의 영역이다.
- `state` 에 추가할 필드는 **객체 끝(`canHold:` 다음)**에 넣어라.
  `level` 주변은 T-005a 의 영역이다.
- 너는 `state.score` 를 **읽기만** 한다. T-005a 가 그 값을 어떻게 계산하든
  상관없다. 점수 계산 코드를 만들지 마라.

## 기존 코드에서 반드시 지킬 것

- 터치는 기존 의도 객체 경로를 쓴다: `pushIntent({type:'move',dx})`,
  `{type:'rotate',dir}`, `{type:'softDrop',active}`, `{type:'hardDrop'}`,
  `{type:'hold'}`. **새 의도 타입을 만들지 마라.** 키보드와 같은 경로여야 한다.
- 터치 핸들러가 `state` 를 직접 고치면 안 된다 (T-002 의 INPUT/LOGIC 분리).
- 일시정지·게임오버 중에는 터치도 무시된다. 기존 `ui.isPaused || state.isOver`
  가드를 재사용한다.
- 색상·간격은 `:root` 커스텀 프로퍼티로. JS 에 hex 리터럴을 남기지 마라.
- 외부 리소스 금지. 아이콘도 CSS/텍스트로 만든다.
- 모션은 `transform`/`opacity` 만. `prefers-reduced-motion` 을 존중한다.

## 명세

**터치 제스처.**
- 좌우 스와이프: 한 칸 이동. 계속 끌면 `CONFIG.SWIPE_CELL_PX` 마다 한 칸.
- 아래로 스와이프(빠르게): 하드 드롭.
- 아래로 끌기(느리게): 소프트 드롭.
- 탭: 시계 회전.
- 임계값(스와이프 거리·속도)은 전부 `CONFIG` 에.

**화면 버튼.** 좁은 화면에서 보드 하단에 조작 버튼을 둔다:
좌 · 우 · 회전 · 홀드 · 하드드롭. 버튼도 의도 객체를 만든다.
넓은 화면에서는 숨긴다.

**최고 점수.** `localStorage` 키 `CONFIG.HIGH_SCORE_KEY`. 게임오버 시
`state.score` 가 저장값보다 크면 갱신한다. 사이드 패널에 표시한다.
localStorage 를 쓸 수 없는 환경(`file://` 제한, 예외)에서 **게임이 죽으면
안 된다.** try/catch 로 감싸고 실패 시 세션 내 값만 유지한다.

**레이아웃 정리 (T-007).**
1. 보드 하단의 약 170px 죽은 공간을 없앤다. 콘텐츠를 뷰포트에 대해
   수직으로 정렬하거나 높이를 채운다.
2. HOLD 박스가 비었을 때 생기는 시각적 구멍을 처리한다 (빈 상태 표시).
3. 오른쪽 조작 안내 텍스트의 대비를 높인다.

## Acceptance criteria

1. 좌우 스와이프가 `state.piece.x` 를 바꾼다. `touchstart`/`touchmove`/
   `touchend` 를 합성해 주입하고 이동 전후 `x` 를 보고한다.
2. 탭이 `rot` 을 1 증가시킨다.
3. 빠른 아래 스와이프가 하드 드롭을 일으킨다 (`lockedCount` +1).
4. 터치 핸들러가 `state` 를 직접 수정하지 않는다. `pushIntent` 를 거치는
   것을 코드 위치로 보인다.
5. 일시정지 중 터치가 무시된다 (`state.piece` 불변).
6. 화면 버튼 5개가 좁은 화면(≤`CONFIG.TOUCH_UI_MAX_PX`)에서 보이고 넓은
   화면에서 숨는다. 두 폭에서의 표시 여부를 보고한다.
7. 게임오버 시 최고 점수가 저장되고 다음 로드에서 표시된다.
   저장 전후 `localStorage` 값을 보고한다.
8. 저장값보다 낮은 점수로 게임오버되면 최고 점수가 갱신되지 않는다.
9. `localStorage.setItem` 이 예외를 던지도록 만든 상태에서도 게임이
   계속 동작한다 (에러가 루프를 멈추지 않는다).
10. 320px 폭에서 가로 스크롤이 없고 버튼이 화면 안에 들어온다.
    `scrollWidth` 와 `clientWidth` 를 보고한다.
11. 보드 하단 죽은 공간이 없어졌다. 1100x820 뷰포트에서 콘텐츠 하단과
    뷰포트 하단의 간격을 픽셀로 보고한다.
12. HOLD 가 비었을 때 빈 상태가 시각적으로 처리된다. 무엇을 했는지 한 줄로
    설명한다.
13. LOGIC 섹션, `applyLineClears`, `lockAndSpawn`, `tryRotate` 가 변경되지
    않았다 (`git diff` 로 보고).
14. T-004 기준 3, 4 가 여전히 성립한다 (일시정지 중 `advance` 미호출,
    키 입력 무시).
