# T-002 — 입력: 이동 / 소프트·하드드롭 / 단순 회전

Phase: 1 · Status: Ready · Depends on: T-001 (`eec2f2b`)

## Summary

T-001 이 만든 `tetris.html` 에 사용자 입력을 붙인다. 키보드로 조각을 좌우로
옮기고, 빠르게 내리고, 즉시 바닥에 꽂고, 회전시킬 수 있게 한다. 이 태스크가
끝나면 "게임"이 된다 — 지금은 조각이 저절로 떨어지는 것만 볼 수 있다.

회전은 **단순 회전**만 구현한다. 회전 결과가 벽이나 블록과 겹치면 회전을
취소한다. 월킥으로 밀어내는 것은 T-003 이다.

## 기존 코드에서 반드시 지킬 것

T-001 이 만든 구조를 따른다. 새 구조를 만들지 않는다.

- 입력 처리는 `INPUT` 섹션 주석 자리에 넣는다. 지금 그 자리는 비어 있다.
- **INPUT 은 규칙을 실행하지 않는다.** 키 이벤트를 의도 객체로만 바꾼다:
  `{ type: 'move', dx: -1 }`, `{ type: 'rotate', dir: 1 }`,
  `{ type: 'softDrop' }`, `{ type: 'hardDrop' }`.
  그 의도를 LOGIC 에 적용하는 것은 LOOP 의 `advance()` 책임이다.
  키보드와 터치(T-005)가 같은 경로를 쓰게 하기 위한 분리다.
- 조각 갱신은 `movedDown()` 처럼 **새 객체를 반환하는 순수 함수**로 추가한다:
  `movedBy(piece, dx, dy)`, `rotated(piece, dir)`. 원본 piece 를 변형하지 않는다.
- 충돌 판정은 기존 `collides(board, piece)` 를 재사용한다. 새로 만들지 않는다.
- 회전 상태는 `CONFIG.SHAPES[id][rot]` 에 이미 4방향 데이터가 준비되어 있다.
  `rot` 을 `(rot + dir + 4) % 4` 로 옮기고 `collides` 로 검사만 하면 된다.
- 새 튜너블 값(DAS, ARR, 소프트드롭 배속, 하드드롭 점수)은 전부 `CONFIG` 에.

## Scope

포함:
- `keydown`/`keyup` 리스너와 의도 큐
- ← → : 좌우 1칸. DAS 167ms 후 ARR 33ms 간격 자동 반복
- ↓ : 소프트 드롭 (낙하 간격을 `CONFIG.SOFT_DROP_DIVISOR` 로 나눔). 키를 떼면 원복
- Space : 하드 드롭 — 더 못 내려갈 때까지 즉시 이동 후 **그 자리에서 바로 고정**
- ↑ 또는 X : 시계 회전 / Z : 반시계 회전. 겹치면 취소(no-op)
- O 조각은 회전해도 모양이 같다. 별도 분기 없이 테이블 조회로 처리된다

제외 (다른 태스크):
- SRS 월킥, 7-bag, 홀드, 고스트, 락 딜레이, 라인 클리어, 점수 → T-003
- 사이드 패널, 디자인 → T-004
- 터치 조작 → T-005
- 일시정지/재시작 키 → T-004

## Acceptance criteria

각 항목은 브라우저 콘솔에서 `state` 를 읽어 즉시 확인 가능해야 한다.

1. `state.piece` 의 `x` 가 ← 1회에 정확히 1 감소, → 1회에 1 증가한다.
   벽에 닿은 상태에서 더 누르면 `x` 가 변하지 않는다 (`collides` 가 막는다).
2. ← 를 누른 채로 유지하면 **첫 이동 후 167ms 뒤**부터 33ms 간격으로 반복
   이동한다. 두 값은 `CONFIG` 에서 온다. 콘솔에서 CONFIG 값을 바꿔 확인 가능.
3. ↓ 를 누르고 있는 동안 낙하 간격이 `CONFIG.DROP_INTERVAL_MS /
   CONFIG.SOFT_DROP_DIVISOR` 가 되고, 떼면 즉시 원래 간격으로 돌아온다.
4. Space 1회에 조각이 최하단까지 내려가 **같은 프레임에 고정**되고 새 조각이
   스폰된다. `state.lockedCount` 가 1 증가한다.
5. 회전 시 `state.piece.rot` 이 0→1→2→3→0 (시계) 또는 역순(반시계)으로 돈다.
   `state.piece.id` 와 `x`, `y` 는 변하지 않는다.
6. 벽에 붙은 I 조각을 회전시켜 셀이 보드 밖으로 나가는 경우, `rot` 이
   **변하지 않는다**. (월킥이 없으므로 취소가 정답이다.)
7. `movedBy` 와 `rotated` 는 인자 piece 를 변형하지 않고 새 객체를 반환한다.
   호출 전후로 원본 객체가 `deep equal` 이다.
8. 키를 누르지 않은 상태의 동작은 T-001 과 동일하다. 낙하 간격 1000ms,
   프레임레이트 무관. **T-001 수용 기준 3 이 여전히 성립한다.**
9. 입력 코드가 `collides`, `lockPiece`, `pieceCells` 의 시그니처를 바꾸지 않았다.

## Out of scope / 하지 말 것

- 회전이 실패할 때 조각을 밀어내지 마라. 그것이 월킥이고 T-003 이다.
  여기서 미리 구현하면 T-003 의 검증 지점이 사라진다.
- 라인이 꽉 차도 지우지 마라 (T-003).
- 하드드롭 점수를 계산하지 마라. 점수 시스템 자체가 T-003 이다.
- 사이드 패널이나 조작 안내 UI 를 만들지 마라 (T-004).
- 기존 함수를 "더 낫게" 리팩터링하지 마라. 필요한 것만 추가한다.

## Verification

**시간 경과를 기다리지 마라.** 다음처럼 즉시 관측한다.

- 키 입력은 `dispatchEvent(new KeyboardEvent('keydown', {key:'ArrowLeft'}))`
  로 주입하고 `state.piece` 를 직접 읽어 확인한다.
- DAS/ARR 은 `CONFIG.DAS_MS` / `CONFIG.ARR_MS` 를 콘솔에서 작은 값으로 바꾼 뒤
  확인하고 원복한다. 실제 167ms 를 기다리지 않는다.
- 기준 8 은 T-001 때처럼 `advance(deltaMs)` 를 직접 호출해 검증한다.
