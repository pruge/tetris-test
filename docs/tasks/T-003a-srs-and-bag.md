# T-003a — 조각 생성과 회전: SRS 월킥, 7-bag

Phase: 2 · Status: Ready · Depends on: T-002 (`ed0f10e`)

## Summary

두 가지를 고친다. 첫째, 조각 생성을 `Math.random()` 에서 **7-bag** 으로
바꾼다 — 7종이 한 바퀴에 정확히 한 번씩 나온다. 둘째, 회전이 벽이나 블록에
막힐 때 지금은 그냥 취소되는데, **SRS 월킥 테이블**로 조각을 최대 4곳까지
밀어보고 들어가는 자리를 찾는다.

이 태스크가 끝나면 벽에 붙은 조각도 회전하고, 같은 조각이 연속으로 5번
나오는 일이 없어진다.

## 기존 코드에서 반드시 지킬 것

- `rotated(piece, dir)` 는 **지금 그대로 둔다.** 회전 상태만 바꾸는 순수
  함수라는 성질을 유지한다. 월킥은 그 위에 얹는 별도 함수다:
  `tryRotate(board, piece, dir) -> piece | null`.
  계획 문서의 계약대로 실패는 예외가 아니라 `null` 이다.
- `applyIntent` 의 rotate 분기는 현재 `tryReplacePiece(rotated(...))` 다.
  이것을 `tryRotate` 호출로 바꾼다. `tryReplacePiece` 자체는 move 경로가
  계속 쓰므로 건드리지 않는다.
- `collides(board, piece)` 를 재사용한다. 새 충돌 함수를 만들지 않는다.
- `randomPieceId()` 를 `nextPieceId()` 로 대체한다. `spawnPiece(id)` 의
  시그니처는 바꾸지 않는다.
- 큐 상태는 `state` 에 넣는다: `state.bag`(남은 조각), `state.queue`(다음
  조각 목록). T-003c 의 미리보기가 `state.queue` 를 읽을 것이므로
  **최소 5개를 항상 채워둔다.**
- 월킥 오프셋과 bag 크기는 전부 `CONFIG` 에.

## SRS 월킥 명세

회전 시도 순서: 오프셋 5개를 순서대로 적용해보고 `collides` 가 false 인
첫 번째를 채택한다. 5개 모두 실패하면 회전하지 않는다(`null`).
첫 오프셋은 항상 `[0, 0]` — 즉 밀지 않고 그대로 되는 경우다.

- `CONFIG.KICKS.JLSTZ[from][to]` — J, L, S, T, Z 공용
- `CONFIG.KICKS.I[from][to]` — I 전용 (오프셋이 다르다)
- **O 조각은 회전하지 않는다.** 모양 테이블상 4방향이 동일하므로 별도
  분기 없이도 `[0,0]` 에서 성공한다. 분기를 넣지 마라.

`from`/`to` 는 0~3 회전 상태다. 표준 SRS 오프셋 값을 사용하되, **좌표계에
주의하라**: 이 코드의 y 는 아래로 증가한다. 표준 SRS 표는 y 가 위로 증가하는
표기가 많다. 부호를 그대로 옮기면 조각이 반대로 밀린다.

## Scope

포함:
- `CONFIG.KICKS` 테이블 (JLSTZ 8쌍, I 8쌍, 각 5개 오프셋)
- `tryRotate(board, piece, dir)` 순수 함수
- 7-bag: `state.bag` 이 비면 `PIECE_IDS` 를 셔플해 채운다
- `state.queue` 를 항상 `CONFIG.QUEUE_SIZE`(=5) 이상 유지
- `applyIntent` 의 rotate 분기 교체

제외:
- 다음 조각 **화면 표시** → T-003c (지금은 `state.queue` 데이터만)
- 락 딜레이, 라인 클리어, 점수 → T-003b
- T-스핀 판정 → T-005

## Acceptance criteria

1. `tryRotate` 는 성공 시 새 piece 객체를, 실패 시 `null` 을 반환한다.
   인자 `piece` 와 `board` 를 변형하지 않는다 (호출 전후 deep equal).
2. 좌벽에 붙인 세로 I 조각(T-002 기준 6에서 회전이 **취소되던** 배치)을
   회전시키면 이제 **회전에 성공하고 오른쪽으로 밀려난다.** 회전 전후의
   `rot` 과 `x` 를 둘 다 보고한다.
3. 빈 보드 한가운데의 조각을 회전시키면 `x`, `y` 가 변하지 않는다
   (`[0,0]` 오프셋이 채택된다).
4. 5개 오프셋이 모두 막히는 배치를 만들어 회전이 취소되고 `rot` 이
   유지되는 것을 확인한다. 어떤 배치를 썼는지 보고한다.
5. O 조각은 어떤 위치에서 회전해도 4셀의 좌표 집합이 변하지 않는다.
   코드에 O 전용 분기가 없다 (`grep` 결과로 보고).
6. `nextPieceId()` 를 70회 호출하면 각 조각 id 가 **정확히 10회씩** 나온다.
7. 연속 14회 호출 중 같은 id 가 3연속으로 나오지 않는다
   (7-bag 에서는 두 bag 경계에서 최대 2연속까지만 가능하다).
8. 어느 시점에도 `state.queue.length >= CONFIG.QUEUE_SIZE` 다.
   조각을 20개 소비시킨 뒤에도 성립한다.
9. `collides`, `lockPiece`, `pieceCells`, `rotated`, `spawnPiece` 의 시그니처가
   변경되지 않았다 (`git diff` 로 보고).
10. T-002 수용 기준 1~4, 8 이 여전히 성립한다 (좌우 이동, DAS/ARR,
    소프트/하드 드롭, 프레임레이트 무관 낙하).
